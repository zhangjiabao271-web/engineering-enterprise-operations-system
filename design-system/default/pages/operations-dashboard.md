# 经营驾驶舱页面规范

## 页面目的

让经营者在一分钟内判断：有多少在营项目已经能可靠核算，哪些项目仍缺合同、成本、结算、开票或回款事实。

## 信息顺序

1. 项目经营可核算率，并显示“可核算项目数 / 在营项目数”。
2. 已确认项目毛利、应收未收、未归集成本。
3. 全部项目经营闭环表。
4. 合同分配、采购归集、人工归集、结算确认组成的经营闭环索引。
5. 可直接进入对应业务台账的今日优先处理事项。
6. 施工产值不等于收入、利润不等于现金的口径提醒。

## 项目闭环表

固定列为：

- 项目
- 当前阶段
- 结算确认
- 已归集成本
- 确认毛利
- 现金余额
- 当前数据缺口

没有结算确认的项目，毛利显示“待结算”，不得显示一个貌似精确但不可解释的负数。澄湖、蓝湾等项目始终独立成行。

## 视觉与交互

- 采用中性表格行和普通文字阶段，不使用高饱和状态块。
- 页面、侧栏和信息区统一为纯白；模块之间只使用留白、字重和中性细线分隔。
- KPI 保持白底，不使用整卡或右上角提示色块；必要强调只使用铜棕文字或细线。
- KPI 不使用“项、利、收、本”等伪图标或方形文字占位符。
- 闭环索引只展示真实覆盖率，采用铜棕细线串联，不使用装饰性流程图。
- 项目表占页面主要宽度，驱动指标为右侧窄栏。
- 右侧窄栏只保留可处理待办，不重复展示闭环索引中已有的覆盖率。
- 双击项目行进入项目经营核算。
- 1200×800 下四个指标保持单行，项目表自身滚动。
- 刷新只重新读取经营视图，不改变业务数据。

## 正式口径

在营项目同时存在有效合同项目分配和有效结算确认时，进入“可核算”状态。合同、结算、发票、回款和成本必须来自各自正式事实模块。
