# 合同与结算页面规范

## 历史业务归属保护

- 合同改经营主体或更换补充协议上级时，预览和保存都校验继承影响；不能让关联有效资金流水或进项票与来源单据的主体矛盾，也不能变成未知归属来绕过保护。失败整笔回滚，不保存备注或审计的半成品。
- 变更上级合同后，在同一事务内重新核对派生发票抵扣；已单独确认的票面主体、项目收入和实际到账金额保持原事实。
- 已有关联项目、收入、发票或回款的合同不能直接更换客户；未使用资料允许更正，未知客户仅按明确一致的关系补齐。错误在原弹窗内解释并保留输入。

## 合同计价

- 年度框架合同新增时默认“单价据实结算”；用户已手动选定计价方式时不覆盖，编辑历史合同保持原计价方式。
- 固定总价显示“含税合同金额”，并继续作为项目分配和收入确认的硬边界。
- 暂定总价显示“暂定金额”；超过时明确提示，但不阻止收入确认。
- 单价据实结算不显示合同金额，说明口径为“实际工程量 × 协议单价”。
- 暂定总价和据实结算可填写独立控制上限；控制上限只预警，不改写合同金额。

## 渐进表单

- 据实年度合同可选择“随回款补足实际结算”：超过本项目、本合同既有确认的回款同步新增结算；以后开票仅关联已有结算。启用时明确告知回款同时证明结算，历史预收和待分配回款须先核对。
- 已确认结算独立保留。调减／作废关联回款时必须预览并明确选择“保留真实结算”或“撤销录错的自动补足收入”；只有明确撤销才调减对应自动收入，已有发票或其他回款占用时拦截。自动补足收入不能从收入确认入口单独修改／作废，普通手工结算仍沿用原入口。

- “计价方式”控制金额字段：无关字段必须隐藏，不留空白占位。
- 据实模式金额隐藏并禁用；固定／暂定模式要求填写各自对应金额标签，控制上限只在暂定／据实模式出现。
- 所有金额字段保留可见标签，错误在当前弹窗内反馈并保留已输入内容。
- 日期继续使用日历选择器，保存和取消固定在弹窗底部。

## 台账表达

- 计价方式和客户名称必须完整显示；长中文自然换行，宽表在表内横向滚动，操作列不得覆盖数据文字。
- 顶部支持项目筛选。由项目经营核算跳入时预选该项目，并同时筛选合同、项目分配和收入确认；合同约定金额仍是整份合同口径，不误称为该项目金额。
- 顶部“返回上一级”回到进入前的经营核算或台账，恢复原项目范围、页签、查询、分页和滚动位置；无需手动从侧栏重找页面。
- 合同台账依次展示计价方式、约定金额、控制上限、累计确认和涉及项目数。
- 据实结算的约定金额显示“据实结算”，不显示为零元合同。
- 项目数按项目分配与收入确认项目的并集统计。
- 累计确认超过暂定金额或控制上限时标记“超额”，合同原值不得随累计确认变化。

## 合同与项目关系

- 合同表单可直接确认实际经营主体。关联项目自动沿用合同主体，经营主体页同时显示归属来源和状态；多份关联合同主体不一致时保留冲突待处理，不自动猜测。

- 资料分析入口分开展示“已上传附件”和“已加入分析资料”；未加入分析的原附件应直接可见，不用空资料计数掩盖已上传文件。
- 网页资料首次读取默认调用已配置模型，PDF/图片提供原始页面，其他格式提供完整原文及位置；同时提供最小项目、合同、我方主体名称和资金分析目的。不新增“AI重新识别”按钮，不自动重发历史附件。既有读取动作前说明发送范围及模型费用。
- 预览先显示业务理解摘要，再显示收付款节点、系统复算金额、相对期限和前置条件；原文依据可展开。缺页、不可读、归属不明及待补条件不得进入确定时间表。
- 模型结果保留原文位置、文件哈希、模型名和范围指纹。核对确认控件不预选，取消不关联资料、不删除原件、不生成账目；只读入口只允许预览。接口失败或输出不完整明确报错，不以本机OCR结果冒充模型理解。

- 固定总价和暂定总价合同使用正金额项目分配；单价据实合同使用零金额项目关联，台账显示“据实关联”而不是“0元分配”。
- 收入确认的“合同与项目”只能来自当前有效的真实关联/分配，不得临时组合任意合同和正式项目。
- 正式合同收入保存时由服务层再次校验关系；据实和暂定合同要求已关联，固定总价还要校验累计收入不超过项目分配额。
- 合同与项目客户不一致时禁止建立关系，避免收入和成本串到其他客户。
- 历史固定总价或暂定总价合同允许修正为单价据实结算：保存前提示影响，并在同一事务内把有效金额分配改为零金额据实关联；收入确认、发票和回款归属保持不变。
- 已有项目关系或收入确认的据实合同，不允许直接反向改为固定总价或暂定总价，避免凭空产生合同金额和分配边界。

## 零星现金工程边界

- 已设置约定总额的现金项目，收入确认弹窗显示约定总额、除本笔外已确认金额和本笔最多可确认金额。
- 达到约定总额后，确认金额输入进入不可用状态；服务层仍必须在新增和修改时再次校验，界面状态不能代替业务规则。
- 未设置约定总额的现金项目继续允许多笔完工确认，界面明确提示“未设总额”，不把它误显示为零元项目。
