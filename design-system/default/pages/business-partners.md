# 客商档案与经营概览

- 主任务是识别并维护唯一往来主体，不把客户和供应商拆成两份重复单位资料。
- 通用客商列表优先展示主体名称、角色、状态、主要联系人和统一社会信用代码。
- 同一客商允许同时拥有客户、供应商、分包商等角色。
- 共同资料只维护一次；客户与供应商特有字段在编辑弹窗中分区呈现。
- 已被项目、合同、采购或报价引用的角色不得直接移除；历史记录通过停用保留。
- 待确认档案必须可见，不能混同为已启用正式档案。

## 供应商类型

供应商按“生产厂家 / 经销门店”页签分开显示，页签显示当前搜索和状态条件下的数量，共用整页宽度的表格。有匹配的未分类记录时显示“待分类”页签，为零时隐藏。移除重复的类型下拉筛选和表格类型列；重置搜索和状态时保留当前页签。新增及编辑档案仍可设置类型，保存后切换至对应可见页签；旧档案不按名称推断类型。类型独立于产品范围，不影响采购、报价和项目成本。

## 客户经营列表

以下为现有桌面客户列表规范；本机网页的本轮经营概览以文末专节为准。

- 客户档案主列表承担经营查看任务，字段为客户名称、本年业务额、本年实际回款、当前未回款、在做项目、最近业务、主要联系人、电话和异常状态。
- 本年业务额按所选年度的有效收入确认日期汇总，不使用合同金额；年度框架合同随实际收入确认自然更新。
- 本年实际回款按到账日期汇总；当前未回款按截至当前的全部有效收入减全部有效回款计算，不得误标为年度值。
- 客户归属优先采用项目的客户主体；项目未关联客户时才回退合同客户，同一业务事实只能归属一次。
- 默认展示当前年度，并允许切换到已有业务年度。最近业务取当年收入确认、开票或回款日期中的最近日期。
- 在做项目仅统计“筹备中”和“进行中”；正常启用状态弱化显示，待确认和已停用作为异常状态显示。
- 客户编码、客户分类、结算条款、信用额度、备注和开票银行资料保留在档案编辑窗口，不占用经营主列表。
- 双击客户或点击“查看业务”进入项目维度明细，分别呈现本年业务额、本年开票、本年回款和当前未回款。

## 本机网页端中文标签

- 客户经营概览使用“经营年度”“年度收入（已确认）”“年度实际回款”“全周期未收（已知）”“在做项目”。年度值随所选年度变化，当前余额仍取全部已录入的全周期有效事实；最近往来取全周期最近三项，不冒充当年业务。
- 详情、指标、业务证据与修改历史共用中文字段名称，不直接显示数据库英文键。状态按所属业务解释，不能把启用的客户档案误写成合同“履约中”。
- 只修改界面表达，不改数据库字段、收入归属或金额计算；未知新字段显示中文待完善提示，并由字段覆盖验收发现遗漏，不凭字段名猜测业务含义。

## 第三阶段：本机网页客商经营概览

### 视觉与交互

- 保持现有浅色工作台：白色表面、`#F5F5F7` 页面底色、`#1D1D1F` 正文、`#63636B` 辅助文字、`#0066CC` 操作色；字体沿用微软雅黑 UI / Segoe UI，不加载网络字体、不新增动效。
- 顶部最多四项指标，下方为年度、搜索、档案状态及经营表格。年度为业务年度，不是签约年份。页签、搜索、状态仅筛选档案行，顶部合计和占比分母保持 API 当前范围，文案明确说明。
- 客户展示收入、到账、未收、在做项目、贡献／未收占比、最近往来及联系资料。客户名称和“档案”复用 `detailRecord`，编辑和新增复用 `editRecord`，只读状态隐藏新增／编辑。
- 供应商使用“生产厂家 / 经销门店”页签，匹配的未分类档案显示“待分类”；数量先按搜索和状态计算，再分组，不按名称推断供应商类型。重置搜索保留分组。档案资料复用原编辑器，报价／采购直接跳原列表。
- 占比为整数基点，一位小数显示，保留金额分子／分母及细条辅助表达。分母为零显示暂无完整分母；存在总额待确认旧账时不显示看似精确的未收占比。
- 金额跳转原项目／采购台账，不增加一套客商明细弹窗。年度采购额及单数链接携带所选年度，动作栏“采购”仍看全周期；进项票跳原票据视图。最近收入／回款／票据／采购直接调用原 `detailRecord(module,id)`；旧账只跳独立旧账视图，不混用工程项目 ID。
- 760px 以下同一语义表格改为逐档案纵向排布，保留列标签；名称、长说明自然换行，金额保留两位小数，不截断。触控目标至少 44px，键盘焦点可见；不新增水平页面溢出。

### 服务与口径

入口：`services.partner_overview_service.get_overview(role, year=None, project_id=None)`。

- `role` 接受 `customers` / `suppliers`，也兼容单数。年份默认本年，限定 1900–9998。项目为空为全公司，非空验证真实存在；不存在报错，不静默降为全公司。
- 使用 `db_read` + `use_read_snapshot`；共同档案复用 `master_data_service.list_business_partners`，供应商特有字段复用 `list_suppliers(active_only=False)`，旧账复用 `historical_receivable_service.list_projects`。不迁移、不写账、不按名字建立归属。
- 收入只取有效 `settlements.amount_minor`，年度只按 `settlement_date`。合同签约额、合同年份、施工产值、业务形成日期和发票金额不替代收入。无合同及现金工程同样纳入。
- 客户首先按项目客户主体归属；项目缺客户才回退该笔收入／回款明确关联的合同客户。关联收入的回款优先沿用该收入的合同客户，不从其他合同或相同名称猜配。
- 年度到账按 `receipt_date`；回款记录与分配都必须有效，关联收入还必须有效且属于同一项目。每条有效分配只读一次，不能把整笔到账重复 JOIN 到多个合同／收入。公司范围内明确关联客户的独立旧账到账另加一次，并保留 `yearly_historical_receipt_minor`。
- 同一笔到账的有效分配合计超过实际金额时，该笔全部留待核对，不拆出虚假客户实收；计入 `overallocated_receipt_count`，公司范围的实际金额保留在未分配提示中。
- 全周期未收先逐客户／项目计算：有效收入减已关联收入的有效到账，不低于零；项目间不互抵。已明确项目但未关联收入的预收／待分配到账单列 `pending_receipt_minor`，不抵未收。
- 公司范围再加明确客户的已知旧账余额 `historical_receivable_minor`，不增加工程收入。旧账总额为空时保留 `historical_unknown_count`，未收仅是已知部分，不能当零。工程项目范围不包含独立旧账，即使两类项目 ID 数字相同也不匹配。
- 客户未归属收入／回款／未收与本年无有效分配的到账保留在 `unattributed`；不摊给任何客户。无有效分配到账无法套入工程项目范围，项目查询时明确排除。归属合计不是银行现金总额。
- 在做项目为“筹备中 / 进行中”，直接项目客户或明确业务／合同关系可建立项目集合；每客户、汇总均去重，不因工程改为现金而移除。
- 供应商年度采购按 `purchase_date`，有效采购单头含税含运费总额；多材料一单只计一次。项目范围复用 `purchase_project_costs` 的项目分摊额，不能复制整单总额；单数为涉及该项目的去重采购单数。最近采购不受年度限制。
- 未关联供应商档案的采购保留在 `unattributed`，不能按商户名称猜配。采购“已付款”标记不推导银行现金，也不由未付款标记编造应付。
- 金额全程整数分，返回整数交给现有 `json_value` 字符串化 `_minor`；前端金额用 `money` / `BigInt`，只对有界的基点转 Number。

### 本机网页接入与导航

1. `index.html` 加载 `partners.css` 和经典脚本 `partners.js`；脚本在公共助手定义之后可用，不使用 ES module 隔离作用域。
2. `app.js` 客户／供应商路由分支调用 `await renderPartnerOverview(state.route)`，放在通用档案列表分支之前。
3. `/api/dashboard?view=customers|suppliers&year=YYYY&project_id=...` 转给 `get_overview(view, year, project_id)`，复用现有 JSON 兼容输出。返回 `rows`、`summary`、`years`、`unattributed`、`year`、`project_id` 和口径文本；不新增账本或写入端点。
4. 原列表支持 `#projects?customer=ID`、`#purchases?supplier=ID`、`#offers?supplier=ID`；年度采购额和单数使用 `#purchases?supplier=ID&year=YYYY`，采购快捷入口不带年度。供应商进项票入口为 `#finance?tab=input_invoices&supplier=ID`，原列表精确过滤供应商；合同保留 `#contracts?customer=customer:ID`。最近往来详情复用 `detailRecord`。独立旧账用 `#finance?tab=historical`，回款用 `#finance?tab=receipts`；不使用跨页通用查询 ID 控制台。客户原项目列表与核算分析共用显式项目/合同归属，项目已有客户时不被合同客户覆盖。
5. `state.partnerOverview.customers` / `.suppliers` 分别存 `{year,keyword,status,kind,page}`，`state.partnerOverviewRequest` 防迟到响应。不要改通用 `state.keyword/page/currentRows`。导航快照如需逐历史条目恢复，应深拷贝这两个视图偏好；不保存 API 行数据。
6. 编辑后现有刷新会重新读快照；同角色偏好留在上述独立状态中。客户金额跳原项目台账为全周期，不承诺年度逐笔过滤，页面已明确说明；年度采购链接则明确携带年度。

### 档案维护与旧入口兼容

- 客户、供应商的编辑与停用继续复用原业务操作；停用入口位于“档案操作”，取消不写，已停用和只读模式不显示停用按钮。不复制旧客户经营汇总作为第二套主界面。
- 旧客户服务的年度及累计回款查询同样过滤有效分配。新概览按事实归属和逐项目未收独立统计，不把预收抵到另一项目；旧兼容详情不作为新看板的汇总来源。
- 占比用整数基点与原生 meter 表达，不依赖内联样式；默认选择首个有记录的供应商类型，仍允许手工切到空分组。
