# 数据治理中心

- 人工、采购、项目主数据、履约附件分别呈现待处理缺口，不把未归集误当零成本。
- 禁止按历史名称自动猜测项目；人工归集与采购归集须让用户确认目标项目。
- 批量归集前显示选中条数和目标，保存后刷新缺口；保留原始记录和可追溯来源。
- 空态应说明对应口径当前无缺口，不能笼统显示“暂无数据”。
- 体检指标只表示完整度，不构成收入、利润或现金确认。
- 合同关联与合同附件分列展示：未关联不等于没上传；上传附件不自动创建项目关系。
- 选中项目可进入对应合同页建立关系、查看附件；返回治理中心重新查询正式记录。
- 网页“确认业务经营主体”的业务候选须显示后台返回的名称／单号（`label`），并保留记录编号；有日期、金额和关联项目时一并显示。项目名称与关联项目相同不重复展示，未知金额不伪装成0；只读列表、预览与取消不修改原账目。
- 待归集采购优先呈现材料、规格、数量／过磅重量、计价单价和含税金额，并显示供应商、日期、原单编号、付款状态及备注；整批结算不推定真实数量，多材料保留全部明细，运费另说明。提供只读原单和附件入口。
- 待归集采购数量和金额使用同一有效原单集合，排除已有单项目归属或有效多项目均摊的采购；不能把多项目采购的空头表项目误判为待归集。
- 工天来源呈现日期、工人、作业地点、工作内容、工天和人工成本；批量候选与确认预览同样显示来源和明确目标，取消不写账，保存后清单与统计同步刷新。
- 待归集记录始终为全公司范围，明确说明不受项目筛选影响；项目完整性表遵循项目范围，使用真实项目名称，不只显示编号。
- 进项票关联成本候选保留原单号，同时展示采购材料／规格或费用类别／用途及日期；搜索材料不能丢掉同一单的其他材料。
