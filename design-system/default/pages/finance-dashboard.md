# 开票与回款报表页

## 页面任务

让经营者直接看清确认收入、开票和实际到账，不重复展示同一组金额；需要追溯时再进入项目、发票或回款明细。

## 信息顺序

1. 项目筛选与统计口径。
2. 确认收入、开票进度、回款进度三项核心指标。
3. 独立项目资金进度表：确认收入、开票金额与比例、回款金额与比例、未回款和状态。
4. 销项发票明细：已关联回款、发票余额和结清状态。
5. 回款明细：项目、合同或业务类型、关联发票、收入确认和回款金额。

## 职责边界

- “合同与结算”维护合同、项目分配和收入确认；这里只读取进度，不重复提供维护入口。
- “资金总览”只做公司或项目汇总，不重复放置资金转化链、近期动态等相同数据。
- “销项发票”和“回款记录”分别承载原始单据及修改、作废、附件操作。
- 系统内部可以保留分配逻辑，但界面统一使用“回款”“收入确认”“关联发票”等业务用语，不显示“核销”。

## 数据表达

- 开票进度显示为 `金额 · 百分比`；无需开票的零星工程显示“无需开票”。
- 回款进度显示为 `金额 · 百分比`，并单列未回款金额和“待回款 / 部分回款 / 已结清”。
- 回款必须关联具体收入确认。未选发票时默认按确认日期自动分配，跨多笔确认时允许手动调整。
- 无法无歧义关联的历史回款显示“待分配收入确认”，不把合同累计回款重复显示在每笔收入确认上。
- 发票余额为发票金额减已关联回款；余额为零时进入“已结清”队列。
- 发票明细优先展示价税合计、已关联回款、发票余额和回款状态；合同、收入确认等追溯编号放在其后。
- 回款明细优先展示回款日期、项目、本次回款金额和收入归属；回款单号等内部追溯信息放在其后。

## 视觉与交互规则

- 延续白底、深色文字、细边框和铜棕强调，不增加装饰性图表或重复卡片。
- 顶部只保留三张指标卡，项目表作为页面唯一主任务区。
- 项目必须逐行独立核算，不按客户或年度合同合并。
- 项目筛选同时作用于总览、发票和回款；双击项目行可筛选对应明细。
- 项目资金进度默认显示“待回款”，包含“待回款 / 部分回款”；“已结清”使用同表结构的独立页签承载。
- 回款页签只按确认收入与实际回款判断，不因项目“已完工 / 已关闭”而改变回款状态。
- 新增发票或回款后自动切换到对应明细页签。
