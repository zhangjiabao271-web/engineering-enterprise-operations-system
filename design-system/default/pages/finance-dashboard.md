# 开票与回款报表页

## 历史旧账回收（2026-09-15）

- 第五个页签独立管理历史旧账项目与实际回款，客户来自客户档案。
- 历史项目独立建档，不生成普通施工项目、合同、收入确认或发票分配，不参与年度新增业务收入和现有工程的回款比例。
- 历史欠款总额可以留空，累计收回按实际回款求和；总额未知时余额及结清状态保持待确认。
- 后续可补充总额，总额不得小于已收回金额；总额已确认后限制超额登记。每笔回款和项目变更保留审计记录。
- 本页提供新建历史项目、修改欠款总额、登记历史回款及明细列表；日期使用日历。顶部普通工程筛选不作用于历史页，并在页内明示。
- 收款方式和到账账户缺失时保持待确认；历史回款登记本身不推定银行账户，不自动调整手动资金预算快照。

## 页面任务

让经营者直接看清确认收入、开票和实际到账，不重复展示同一组金额；需要追溯时再进入项目、发票或回款明细。

## 信息顺序

1. 项目筛选与统计口径。
2. 确认收入、开票进度、回款进度三项核心指标。
3. 独立项目资金进度表：确认收入、开票金额与比例、回款金额与比例、未回款和状态。
4. 销项发票明细：已关联回款、发票余额和结清状态。
5. 回款明细：项目、合同或业务类型、关联发票、收入确认和回款金额。
6. 回款跟进：先按项目执行，再按客户汇总查看风险和行动安排。

## 职责边界

- “合同与结算”维护合同、项目分配和收入确认；这里只读取进度，不重复提供维护入口。
- 合同关联不按开票要求排除项目，选择项标明“无需开票”。尚无收入和回款的零星项目关联合同后按合同管理，保留开票要求、历史约定金额和成本；已有零星收入或回款时先核对历史归属，不自动迁移。完工项目仍可补关联历史合同。
- “资金总览”只做公司或项目汇总，不重复放置资金转化链、近期动态等相同数据。
- “销项发票”和“回款记录”分别承载原始单据及修改、作废、附件操作。
- 系统内部可以保留分配逻辑，但界面统一使用“回款”“收入确认”“关联发票”等业务用语，不显示“核销”。

## 数据表达

- 项目资金进度提供“收款完毕”及“结清记录 / 撤销”。仅适用于无需开票的零星现金工程，有有效发票、预收款或历史待分配回款时先核对，不直接抹零。
- 结清窗口展示原确认收入、累计实收和差额，选择抹零/优惠/最终结算调整，并勾选不再收取确认。保存调整前后记录，调减收入及利润、清零应收，不增加回款、不改变施工状态或原约定金额。
- 完全豁免的未收收入记录作废并保留原值，部分豁免直接调减并保留审计快照；撤销恢复原收入。调整有效期间更改收入或回款需先撤销结清。

- 按实际结算的年度合同可单独启用“随开票自动确认收入”。保存发票时同步建立或调整对应收入，不再要求人工重复确认；普通合同仍按原规则。
- 自动模式的开票选择器包含尚无收入的有效合同项目关系，提示“无需另填收入确认”，不显示误导性的待开票上限。价税合计沿用系统含税经营收入口径，不代替财务报税口径。
- 已有收入须与发票逐笔核对后接管，保留原日期及记录；自动收入只能通过对应发票维护。有回款的收入不可直接作废或调低到已回款以下。

- 新增回款自动带出付款人：合同工程优先使用合同客户，零星工程使用项目客户，历史旧账使用历史项目客户；付款人允许手动修改。切换来源只更新空白或上次自动带出的值，保留人工代付人。
- 已保存的付款人作为当时快照保留；修改回款不会重新套用默认客户。历史旧账新增付款人快照字段，旧记录未填写者显示“未记录”，不回填猜测。

- 开票进度显示为 `金额 · 百分比`；无需开票的零星工程显示“无需开票”。
- 回款进度显示为 `金额 · 百分比`，并单列未回款金额和“待回款 / 部分回款 / 已结清”。
- 回款可先于收入登记。默认按本项目、本合同的确认日期自动抵扣，超出部分记为预收款；后续确认收入自动按收款日期抵扣，不新增到账记录、不改变收入归属。
- 零星现金工程回款表单不再要求完工金额或完工日期。历史未明确归属的回款仍标记待分配，不自动解释为预收款；明确选择发票或手动分配的回款继续按原边界校验。
- 无法无歧义关联的历史回款显示“待分配收入确认”，不把合同累计回款重复显示在每笔收入确认上。
- 发票余额为发票金额减已关联回款；余额为零时进入“已结清”队列。
- 发票明细优先展示价税合计、已关联回款、发票余额和回款状态；合同、收入确认等追溯编号放在其后。
- 回款明细优先展示回款日期、项目、本次回款金额和收入归属；回款单号等内部追溯信息放在其后。

## 回款作战台

- 项目视图逐行展示客户、项目、未回款、账龄、承诺付款日、下次跟进日、责任人、当前状态和下一步动作。
- 客户视图只做汇总和下钻，不合并或改写项目级应收事实。
- 账龄默认从最早未结清收入确认日期计算；人工设置应收到期日后，以该日期作为管理口径。
- 每次客户沟通保存独立历史；修改当前计划不得覆盖既有跟进记录。
- 今日需跟进、承诺逾期和 90 天以上应收支持快速筛选。
- 跟进信息不生成、修改或作废结算、发票、回款等财务事实。

## 视觉与交互规则

- 延续白底、深色文字、细边框和铜棕强调，不增加装饰性图表或重复卡片。
- 顶部只保留三张指标卡，项目表作为页面唯一主任务区。
- 项目必须逐行独立核算，不按客户或年度合同合并。
- 项目筛选同时作用于总览、发票和回款；双击项目行可筛选对应明细。
- 项目资金进度默认显示“待回款”，包含“待回款 / 部分回款”；“已结清”使用同表结构的独立页签承载。
- 回款页签只按确认收入与实际回款判断，不因项目“已完工 / 已关闭”而改变回款状态。
- 新增发票或回款后自动切换到对应明细页签。
- 现金回款同步建立完工确认时，显示项目约定总额、已确认和还可确认金额；达到上限后不再提供“新增完工金额确认”，但仍允许选择有未回款余额的既有确认。
- 回款跟进弹窗日期统一使用日历选择；可空日期提供明确的“清空”操作。

## 发票附件可用性

- 销项发票录入窗口顶部提供“选择 PDF 自动识别”，本地读取文字版电子发票，识别只填表不入账；用户确认字段和项目后，发票、自动收入与附件记录在同一事务中保存，失败不留半张账。
- 表单显示未税金额、票面税额及税率，金额以整数分校验。历史未记录税额保持空值，不反算回填；多税率保存文字标记及真实合计税额，不显示成零税率。
- 同客户多个合同或项目只提示候选，不猜测归属。红字、扫描、加密及多发票PDF明确提示不支持，缺失字段为空并要求人工核对，不将缺失识别为0。支持20MB以内、最多10页的单张发票。

- 附件列紧随发票编号和日期，区分“未上传”“已上传 N 个”“文件缺失 N 个”；不能仅根据数据库关联数量判断文件可用。
- 顶部独立筛选行提供“仅看附件待补”，包含未上传和实际文件缺失；保留项目筛选。
- 附件窗口对缺失文件标记“[文件缺失]”，更新附件后刷新发票状态。
- 表格保留可读列宽，并提供横向滚动，避免金额与状态被挤压截断。
