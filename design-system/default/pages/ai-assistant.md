# AI 经营助手页面规范

## 页面任务

让经营者在同一对话中连续追问，并随时看清当前项目、时间、供应商、材料、数据口径和待确认对象。

## 桌面布局

- 左栏：最近会话、新建对话、归档当前对话。
- 中栏：连续消息流、候选确认、来源入口和固定底部输入区。
- 右栏：当前项目范围、已识别条件、数据口径、已加载模块、今日经营提醒和清空上下文。
- 默认仅展开对话区；历史和范围条件按需打开，侧栏互斥，避免三栏同时挤压消息。项目范围在对话顶部始终可见。
- 在 `1200×800` 主窗口下，消息文字自动换行，底部输入区固定，不用放大窗口才能发送。

## 对话规则

- 每个会话保存独立上下文；新建会话不会继承上一个会话的供应商或材料。
- 用户明确确认的供应商、材料和时间范围才进入持续上下文。
- 简称或多候选涉及经营金额时，先显示候选卡片，不强行合计。
- 后续省略式问题可以继承已确认范围，例如“那螺帽呢”。
- 清空上下文仅清除时间、供应商和材料，保留用户明确选择的项目范围。
- 查询期间切换项目范围、清空条件、取消对象确认或切换会话，会取消当前查询并立即允许按新条件提问。旧线程只返回结果，不写回会话；主线程确认仍是当前查询后才保存答案和条件，停止后的未完成回答也不保存。

## 回答规则

- 简单事实优先由本地台账直接计算，不依赖联网模型。
- 项目利润、确认收入、开票、回款、发票余额、客户贡献、客户欠款、成本构成和数据缺口必须由本地服务计算，模型不得自行算数。
- 组合查账由模型理解意图并选择受控查询工具，程序验证条件后在本地只读快照内计算。只发送问题、查询条件和工具目录，不发送整库、附件或原始账目；原有解释型分析继续遵守其数据授权边界。
- 项目范围始终保留正式编号，不能退化为名称筛选；同名项目未指定编号时要求选择，答案来源保留编号。“所有项目”清除上一问的项目名称和编号，按项目比较也以编号分组。
- 发票余额、回款待抵发票、经营待办等已有能力与聚合工具进入同一目录，连续追问可以自由切换或组合。当前快照工具不接受任意期间或筛选条件，不支持时先澄清，不能忽略条件。明确的简单当前状态查询保留离线可用，且更新上一问的查询条件，不继承过时的收入查询。
- 查询计划同时表达回答目的：`leader` 找最大/最小对象，`ranking` 看榜单与比较，`summary` 求合计，`details` 看逐条记录。普通问法由模型规划，不为每个客户或问法新增业务分支。
- 全公司或客户实际回款使用 `collections`，合并现有回款和独立历史旧账，每笔到账只计一次，未分配款仍包含在内。现有项目回款分配使用 `receipts`；历史旧账使用 `historical_receipts`，历史编号与现有项目编号分开。同名旧账项目也须澄清；旧账不新增工程收入、开票或利润，多客户或归属不完整的款项单列待确认。
- 逐条明细可按日期、单号、名称或所选指标升降序排列；字段由工具目录白名单限制，未知值排最后，同值按来源编号稳定排列。排序先于正文和来源明细截断，汇总始终使用全部匹配记录。
- “业务做得最多的客户”默认以已确认收入金额比较，明确问次数时才数记录，并在答案中说明口径。找第一名须检查全部分组和并列，不能只取模型要求的第一条。待归属不冒充客户，未知金额和成本未登记完整的提醒在各种回答形式下均保留。
- 回答标明“本地台账计算”或“DeepSeek 分析”。
- 有逐行来源时提供原始记录入口；来源窗口可缩放、可横向和纵向滚动。
- 查账模式保持只读，经营来源可打开原业务页面。本机网页版另有明确选择的“协助录入”模式，仅支持现有档案上的新增费用、采购、回款和在职工人工天；不提供修改、作废、迁移或实际支付。
- 事实、推断和建议分开；利润、现金、施工金额、结算收入分开。
- “今天该催谁”和“今天做什么”由本地台账生成行动清单；AI 只解释和排序，不自动新增跟进、修改回款或关闭待办。

## 视觉与交互

- 用户消息靠右，使用浅灰圆角内容块，按实际宽度完整换行；不额外添加容易被挤压的“你”标签。助手回答靠左、白底，来源标识使用一行次级文字；消息之间用留白而非横线分隔。
- 对话与输入区共用固定阅读轴，最大参考宽度 780px，窄窗口自然收缩。助手先给结论，再给证据与口径；“谁最多”直接给对象和数值，“看排名”才显示比较表。
- 重试、反馈并入一行，不重复显示整句反馈提问；输入区使用浅灰背景，发送按钮不拉伸为竖条。
- 所有按钮带文字；键盘焦点可见；`Ctrl + Enter` 可以发送。
- 分析期间禁用重复发送，并显示正在核对的数据范围。
- 模型回答采用流式显示；“停止生成”只中断本次展示，未完成回答不写入会话。
- 已完成回答提供“有用/没用”反馈，反馈独立保存，不进入业务事实。
- API Key 使用当前 Windows 账户加密保存，配置文件不得保存明文密钥。
- 输入区固定在消息流下方，消息流独立滚动并自动定位到最新消息。
- 右栏使用“今日经营行动”表达，优先展示到期催款、未安排催款和履约资料待办。
- 回答支持标题、加粗、短段落与原生数据表，不直接展示 Markdown 标记。文本可选中复制，完整回答提供“复制”；全部来源与分组结果收在“查看依据”菜单，重试和反馈作为次级文字操作。
- 已登记收支毛利分析采用“范围 → 汇总金额 → 项目对比表 → 口径与注意事项”。旧回答只转换显示，不改历史消息、金额或统计范围。
- 同类金额右对齐；多行比较使用可排序、可横向滚动的表格，最多显示 8 行高度，全部输出行仍可滚动查看。查询本身有截断时保留原提示。
- 表格沿用同一阅读轴，宽表在内部横向滚动，不把整个对话页撑宽。汇总金额在窄窗口自动换行，输入区与来源入口保持可访问。
- 历史消息按页展示，默认定位最新一页；每页最多 12 条且通常不超过 10,000 字，提供较早／较新消息入口。全部历史和模型上下文保留，不按显示页截断。
- 正文只在已映射、宽度稳定后测量换行；高度变化不重复测量。超过 1,200 字或 24 个换行的段落使用固定高度、独立滚动阅读区，完整内容和复制回答均保留。
- 宽度与上下文换行参数只在变化时更新，避免高度改变反复触发布局。使用隔离进程验证长历史、侧栏展开、980px 窄窗口及 150% 缩放，不用修改正式台账做展示测试。

## 本机网页版

- 协助录入先由外部模型提取用户原话为结构化草稿，不发整库、联系人、工资档案或原附件；只有用户明确勾选模型授权后才调用。模型不计算金额、不猜编号，不自动创建项目、供应商或工人。
- 清单本地解析真实项目／供应商／工人，合并所有缺失问题：未提供日期、税率、数量、付款方式时不擅自填事实。只有整批金额的采购按整批记录，不沿用历史桶价。项目范围不匹配时须切换范围重验。
- 确认窗口展示每项字段及标准项目名称、日期、金额；修改后必须重新预览并重新勾选确认。草稿30分钟有效，账本或归属依据变化后旧确认失效。
- 模型待核对事项与原话可见；不支持的要求不得默默省略，用户须明确处理后重验。回款清单提前展示已有收入分配、预收款或原合同随回款补足结算的影响；助手不另改合同策略。
- 同一清单内重复记录或已通过助手保存的相同业务进入待核对，不静默重复入账。相同金额确实再次发生时，可从原业务入口核对后登记。
- 多笔业务使用同一服务事务保存，任一项失败全部回滚；执行标识持久化，保存成功但响应丢失时同一确认返回原结果，不重复记账。完成后回读逐笔结果并显示已保存，旧草稿入口收起。
- 草稿、取消状态与执行结果独立持久化，不是正式账目或聊天记忆库。经营经验库本轮不做，聊天仍按现有会话生命周期管理。
- 查询答复显示范围、完成时间、事实计算与数据限制；完成时间不冒充历史时点余额。毛利只依据已登记成本，不声称成本完整，依据变化应重新查询。

- 采用独立消息流与底部输入区，不再用经营汇总表代替对话；来源收在回答后的可展开区域。最大阅读轴850px，390px窄屏内部滚动，中文不裁切。
- 默认不勾选外部模型授权；明确勾选后才复用桌面配置，说明只发送问题、已确认条件和工具目录，不发送原始账目与附件。
- 网页会话仅保存在服务器内存，不写桌面会话表；浏览器会话编号可在页面刷新时复用。最近40条的截断提示和服务重启／30分钟未使用失效须可见，不冒充桌面永久历史。
- Enter发送、Shift+Enter换行，中文输入法确认词句不触发发送；停止、清空、换范围及离开页面取消旧查询。候选确认核对当前轮次，客户端不能提交自行构造的查询条件。
- 回答采用安全转义的有限结构化显示，不执行模型提供的HTML、脚本或任意外部链接。表格内部横滚，保留来源及查询本身的截断提示。

## 本机网页桌面窗口补充

- 消息流与固定底部输入区保持同一阅读轴；用户消息靠右，不添加“你”等方形标签，助手正文使用实体底色。
- 欢迎区提供少量明确提问示例，不用经营指标表代替对话。范围、数据来源、授权说明及停止按钮仍可访问。
- 页面动效只作用于呈现，不调度业务查询；离开页面、清空或停止后的旧结果不得写回。正式只读窗口和外部模型授权边界不因原生包装而改变。
